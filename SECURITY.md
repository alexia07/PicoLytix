# Security Policy

## Reporting a Vulnerability

I take the security of PicoLytix seriously. If you discover a security vulnerability, please report it privately rather than opening a public issue.

### How to Report
1.  **Email:** Use the GitHub private reporting feature.
2.  **Subject Line:** Please use "Security Vulnerability - PicoLytix".
3.  **Details:** Include:
    *   A description of the vulnerability.
    *   Steps to reproduce the issue.
    *   PicoLytix version.
    *   Machine OS.
    *   Raspberry Pi Pico board version.
    *   Potential impact (e.g., crash, memory corruption, hardware damage).
    *   Suggested fix (if any).

### What to Expect
*   **Acknowledgment:** I will confirm receipt of your report within **48 hours**.
*   **Investigation:** I will investigate the issue and provide a timeline for a fix.
*   **Disclosure:** Once the fix is released, I will credit you in the release notes (unless you prefer to remain anonymous).

### What NOT to Do
*   ❌ Do **not** open a public GitHub Issue for security vulnerabilities.
*   ❌ Do **not** exploit the vulnerability beyond what is necessary to demonstrate it.

## Security Best Practices for Users
*   Always review the code before flashing to your hardware.
*   Do not use PicoLytix on critical systems where failure could cause physical harm.
*   Keep your firmware updated to the latest version.
